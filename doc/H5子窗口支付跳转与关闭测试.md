# H5 子窗口支付跳转与关闭测试

## 运行与访问

项目使用 Node.js 内置 HTTP 服务，无需安装依赖。项目目录运行 `npm start`，监听 `0.0.0.0:18683`，手机与电脑连接相同局域网后，使用电脑局域网 IPv4 地址访问 `http://电脑IP:18683/html1.html`。根路径也会返回 HTML1。

端口可通过环境变量 `PORT` 修改。PowerShell 示例：`$env:PORT = '18684'`，然后执行 `npm start`。手机无法访问时，检查同一 Wi-Fi、访客网络隔离和 Windows 防火墙的入站规则。

## 三个页面的流程

1. HTML1 点击按钮，通过 `window.open('html2.html', '_blank')` 同步打开子窗口，并保留主窗口。打开失败会提示检查弹窗设置。
2. HTML2 点击模拟支付按钮，通过 `location.href = 'html3.html'` 在当前子窗口跳转。演示不包含支付接口或真实扣款。
3. HTML3 加载后开始 3 秒倒计时，并调用 `window.close()`。如果仍未关闭，则继续留在 HTML3 展示提示。
4. HTML1 通过 `postMessage` 接收阶段通知，通过 `childWindow.closed` 检测子窗口是否关闭，并显示测试记录。页面在后台时，浏览器可能暂停计时器；回到 HTML1 后会继续检测。

## 手机实测与结果判断

从 HTML1 开始操作，不要直接打开 HTML3。依次点击“打开 HTML2，开始测试”和“模拟支付并跳转 HTML3”，等待约 3 秒，观察实际前台页面。

- 如果 HTML3 关闭且前台显示 HTML1，本次手机环境满足测试目标。
- 如果 HTML3 显示“自动关闭未成功”，说明当前环境未允许此次脚本关闭。
- 如果关闭后出现标签页列表或其他页面，记录实际浏览器名称和版本，这是该环境的窗口展示行为。

页面没有通过重定向到 HTML1 或调用主窗口聚焦来模拟关闭结果。HTML1 的“检测到子窗口关闭”只能说明子窗口关闭，是否自动显示 HTML1 仍需观察手机前台。手机浏览器与 App 内置 WebView 应分别实测；计时器也可能受后台或休眠影响。

## 文件职责

- `html1.html`、`html2.html`、`html3.html`：三个独立页面的内容与结构。
- `assets/html1.js`：打开子窗口、记录消息和检测关闭。
- `assets/html2.js`：模拟支付与当前子窗口跳转。
- `assets/html3.js`：倒计时、尝试关闭和失败提示。
- `assets/style.css`：手机适配和共用样式。
- `scripts/server.cjs`：UTF-8 静态服务，仅开放三个页面和指定静态资源，不开放 Git 文件或运行日志。
